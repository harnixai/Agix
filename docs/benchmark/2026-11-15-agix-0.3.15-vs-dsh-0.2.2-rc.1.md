## 2. 测试方法

- **任务。** 六个工程任务：`stats`、`inventory`、`biglog`、`shop`、`audit`、`migrate`。每个任务的素材、给两边的用户消息完全相同。做完后用模型没见过的输入实际运行产物来判定对错；各用例怎么判定，见 [`compare_dsh.md`](compare_dsh.md) §3。
- **token 和调用次数。** 两边各接一个录制代理，从代理读 DeepSeek 在每个响应里报的 `usage`，子 Agent 的调用也算在内。prompt = 未命中 + 命中缓存 + 写入缓存。
- **CPU 和内存峰值。** 取内核的 rusage：
  - 测试自己用 `wait4` 回收 harness 进程，得到它和它等待过的所有子进程的 user+sys CPU，工具命令也算在内。
  - 内存峰值取其中最大的单个进程，实际上就是 harness 进程本身。
  - Agix：最后一轮后正常关掉 `agixd` 再回收，统计的是整个生命期，启动在内。
  - DSH：每轮的 node 进程各自回收，各轮相加，进程启动同样在内。
- **补充采样。** 每 100 ms 用 `ps` 采一次，得到不含工具的 harness 自身 CPU 和整棵进程树的内存和。采样值是下限。
- **墙钟。** 从第一轮发出到最后一轮结束。DSH 的含每轮的进程启动；Agix 的 daemon 这时已经起好了。

## 5. 分析

### 5.1 资源

- **CPU。** Agix daemon 的整个生命期，含启动、建会话、全部轮次和关闭：
  - 简单用例 0.5–1.0 s，`audit`（4 个子 Agent）约 3 s；
  - 其中不含工具的自身 CPU 只有 0.15–1.9 s。

  DSH 光是自身就 1.8–9 s。
- **DSH 的 CPU 开销大致是两块。**
  - 每轮固定开销：起一个 node 进程，加载 JS，约 1.5–2 s。`biglog` 只有 6 次调用、8 秒，也要 1.9 s。
  - 随调用次数增长的部分。
- **`audit` 第 1 轮 DSH 用了 41.9 s CPU。** 其中自身进程约 11.4 s（采样），其余是它起的子进程：这一轮它跑了 162 次工具调用、104 次模型调用。
- **内存。**
  - Agix 的 daemon 在建会话前约 15 MB，最高一次 25 MB（`migrate`）。
  - DSH 的 node 进程一启动就到约 280 MB，`audit` 到 305 MB。
  - 整棵进程树（采样）：Agix 30–49 MB，其中约一半是工具命令（`python3`、`bash`、Seatbelt 包装）；DSH 280–394 MB。
- **对宿主的意义。** Agix 一个 daemon 承载全部会话；DSH 是每个会话一个约 280 MB 的进程。

### 5.2 token 与上下文

- **固定前缀：两边相当。** 首个带工具请求 Agix 是 5811–6006 token，DSH 是 5690–5889。
  - Agix 每次多大约 100–120 token。
  - Agix 的系统提示更长（5027 字节对 2633），工具表更短（20 个工具、15066 字节，对 24 个、19194 字节）。
- **缓存命中率：两边都在 91%–97%。**
- **累计 prompt 基本由调用次数决定。** 每次调用都要把整段对话重读一遍。
  - 每个用例里 prompt 的高低和调用次数的高低方向一致。
- **单次最大上下文：Agix 在四项里明显更小。**
  - `audit` 22K 对 41K；`inventory` 12.4K 对 17.5K。
  - `biglog`、`migrate` 两边持平。
  - `biglog` 的日志文件两边都没有读进上下文。

### 5.3 各用例

- **stats。** Agix 三轮是 4/5/5 次调用，DSH 是 7/5/6 次；prompt 少 34%，快一倍。
- **inventory。** Agix 三轮的调用次数在 8–10，很稳；DSH 是 7–13（49K–184K）。
  - prompt 少 39%，快 46%。
  - 0.3.7 时这是 Agix 唯一 token 更多的用例，这次反过来了。
- **biglog：Agix 唯一明显落后的一项。** prompt +52%，墙钟 +51%。
  - 多出来的调用是 `Bash` 反复交叉核对答案：awk 算完之后又用 grep 或 python 再算一遍。
  - 绝对量很小：多 17K token、慢 4 秒。
- **shop。** token 持平（125K 对 127K），快 22%。Agix 三轮很稳（117K–126K），DSH 是 90K–154K。
- **audit：差距最大。** prompt 369K 对 1.74M（−79%），墙钟 70 s 对 141 s，CPU 3.1 s 对 17 s。
  - 三轮 Agix 都派了 4 个子 Agent，三轮都通过全部校验。
  - Agix 三轮是 321K–396K，非常稳；DSH 是 850K–2.33M。
  - 和 0.3.7 时 Agix 的 935K 相比少了约 60%，这次没有逐版本二分出原因。
  - 第 1、3 轮主 Agent 在派子 Agent 之前先读了一部分模块，派完之后又全量核对一遍，主对话里有重复阅读。
- **migrate。** 墙钟持平，prompt 多 20%（153K 对 128K）。
  - Agix 的主对话会先 `Read` 四个模块看清调用写法，再写一个迁移脚本一次改完，比 DSH 多一两次调用。
  - DSH 第 3 轮因为 50 次工具调用涨到了 290K。

### 5.4 和 0.3.7 那次对照

0.3.7（`Agix-v0.3.7-2026110703`）同样是 DSH 0.2.2-rc.1、三轮中位数，但那次是**两边同时跑**、Agix 在测试进程内运行。所以墙钟只能看大致趋势，token 可以直接比。

| 用例 | Agix prompt 0.3.7 → 0.3.15 | DSH prompt 当时 → 这次 | Agix 墙钟 0.3.7 → 0.3.15 |
|---|---|---|---|
| stats | 30.6K → 29.3K | 58.0K → 44.5K | 19 s → 13.3 s |
| inventory | 83.2K → 75.0K | 73.2K → 122.7K | 31 s → 26.9 s |
| biglog | 50.2K → 50.1K | 51.2K → 33.0K | 17 s → 13.2 s |
| shop | 118K → 125K | 134K → 127K | 23 s → 21.2 s |
| audit | 935K → 369K | 1.03M → 1.74M | 121 s → 69.6 s |
| migrate | 150K → 153K | 226K → 128K | 30 s → 28.2 s |

- Agix 除 `audit` 外，五个用例的 token 都在 ±10% 以内。
- DSH 自己两次的中位数差得更多：`inventory` +68%，`migrate` −43%，`audit` +69%。
- 墙钟下降，有一部分是因为这次两边轮流跑。

## 6. 局限

- **三轮偏少。** DSH 的 `audit`、`inventory`、`migrate` 都有一轮远离另外两轮。token 结论看方向，不看精确比例。资源读数三轮之间很稳。
- **内存口径。** 内存峰值是单个进程的最大值。进程树的总和只有采样值，是下限。
- **测量环境。** 测量在虚拟机里，宿主上有别的负载。两边轮流跑，承受的背景负载相同。
- **代理开销没有计入。** 录制代理在测试进程里，两边都一样，都没算进去。
- **沙箱开销算在 Agix 一边。** Agix 的 `Bash` 经 Seatbelt 包装，这部分开销算在 Agix 一边；DSH headless 有没有类似的包装，这次没有核实。
